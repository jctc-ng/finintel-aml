HOW THIS VERSION HANDLES DATA

Upload the transaction file. The analysis runs in your browser.

CSV and XLSX files are read locally on the analyst's device. This MVP does not upload transaction records to GitHub or to a FinIntel server.

Important

Use sanitised/demo data on the public GitHub Pages deployment. Real STR/SAR, KYC, bank and intelligence data should only be processed in an approved protected environment.

Different institutions use different column names. Map what your file calls each field. At minimum, map a date and either (Amount + Direction) or (Debit + Credit).

STEP 3

Configure analysis

Reference amount is analyst-configured.

It is not presented as a legal or regulatory threshold. Set it according to the case, institution, product and applicable policy.

DIRECTION LOGIC

How FinIntel determines inflow and outflow

  1. If a Direction column is mapped, FinIntel uses values such as credit/inflow/CR and debit/outflow/DR.
  2. If Debit and Credit columns are mapped, positive Credit is inflow and positive Debit is outflow.
  3. If neither is available, FinIntel can infer direction when the subject appears in Originator or Beneficiary.

ANALYST CONTROL

What the system does not decide

  • It does not determine that money laundering or terrorist financing occurred.
  • It does not substitute for KYC/CDD, source-of-funds verification, legal analysis or human intelligence judgment.
  • Indicators are explainable screening outputs for analyst review.
  • False positives and legitimate explanations must be assessed before escalation.
